1. INTRODUCTION                                              *incognito-intro*

incognito points gitsigns at the merge-base of the current branch and the MR
target, so the changed lines of the MR are marked in normal buffers. In
structural mode the marks come from difftastic (`difft --display=json`):
lines that changed only in formatting are dimmed, deleted lines are shown as
virtual lines, and a side-by-side pane shows the base version.

Reviewed marks and the chosen target are stored in a JSON file in the git
common directory.

Requirements: Neovim >= 0.11, gitsigns.nvim, snacks.nvim (pickers), `difft`
0.70 or 0.71 (structural mode). Run |:checkhealth| `incognito`.

==============================================================================
2. COMMANDS                                                  *incognito-commands*

                                                             *:Incognito*
:Incognito {sub} [target]

  on          Review against the merge-base with the target.
  structural  Same, with difftastic signs.
  off         Leave review mode.
  change_base Alias of base.
  head / change_head [rev]
              Choose R: a branch, Git expression (HEAD~2), or SHA search.
              With no argument opens a picker; invalid/ambiguous input is refused.
  range       Clean read-only L -> R overview, without experiments.
  base        Pick the target branch. Text that matches no branch is
              taken as a revision, e.g. HEAD~1 or a hash.
  files       Picker of changed files with reviewed marks (✓ reviewed,
              ~ changed since marked).
  commits     Picker of MR commits (✓ when all changed files are reviewed).
              Selecting one enters commit mode,
              which checks that commit out in a separate worktree and
              opens the files from there. Your checkout is not touched.
  next        Next commit in commit mode.
  prev        Previous commit in commit mode.
  tip         In commit mode, switch the window between the file at the
              commit and the same file in the working tree, on the same
              line of code. The working tree file is diffed against the
              commit, so its signs show what changed after it. Renames
              are followed; a file deleted later is reported.
  reviewed    Toggle the reviewed mark of the current file. In commit mode,
              marks are stored separately for each commit and target.
  since       Diff the current file against the commit it was reviewed at.
  deleted     Toggle deleted lines (structural mode).
  split       Toggle the side-by-side base pane (structural mode).

`on`, `structural`, `files`, `reviewed` and `since` take an optional target.

Lua functions with the same actions: `require("incognito").on()`,
`structural()`, `off()`, `base()`, `files()`, `commits()`, `next_commit()`,
`prev_commit()`, `toggle_tip()`, `toggle_reviewed()`, `since_review()`,
`nav("next"|"prev")`, `toggle_deleted()`, `toggle_split()`,
`change_base()`, `change_head([rev, owner])`, `range()`.

MENTAL MODEL AND DIFF

Source is the ordinary checkout controlling the review. target is the left
revision; L=merge-base(target,R). R is a pinned full SHA, independent of N, the
inspected commit. Review is the detached worktree physically on N. Choose R
with change_head; choose N with commits/next/prev. External branch movement
never silently moves R. The list is git log --reverse L..R, not an inclusive
interval or first-parent walk. Empty ranges remain empty. Changing only base
retains N/edits; N outside the new range is reported, not reset automatically.

Commit files/preview compare first-parent(N) -> N+disk edits, including new
non-ignored files without staging; root commits use an empty tree. Structural
signs use current buffer text, including unsaved edits; Git previews use disk.
Range is a separate clean L -> R view, not an accumulation of experiments.
Outside commit mode the old view is Source+edits, not a clean R snapshot.
Tip opens the real possibly-dirty Source file: edits there change Source.
Reviewed means content was read, not accepted/committed/snapshotted. Since uses
its recorded Git commit, not a backup of arbitrary local edits.

Metadata: <git-common-dir>/incognito-reviews/*.json records ownership, paths,
target/L/R/N and transition phase, separately from existing reviewed marks.
Reopening the same R resumes its previous N and disk/index without reset.

3. CONFIGURATION                                             *incognito-config*

`setup()` is optional. Defaults: >lua
    require("incognito").setup({
        remote = "origin",
        targets = { "main", "master" },
        keymaps = { prefix = "<leader>i" }, -- false disables defaults
        commit_mode = {
            -- worktree_dir = "/absolute/canonical/path/to/reviews",
            link = {},
            lockfiles = { "package-lock.json", "npm-shrinkwrap.json",
                "pnpm-lock.yaml", "yarn.lock", "bun.lock", "bun.lockb" },
        },
        difft = { cmd = "difft", debounce_ms = 300 },
    })
<
DEFAULT KEYS                                                *incognito-keymaps*

Normal-mode defaults are installed when the plugin loads, even without setup().
Set mapleader before loading the plugin. With Space as leader, <leader>ih means
Space ih. For lazy.nvim, use `lazy = false, opts = {}` to install keys at startup;
command-only lazy loading installs them only after the plugin is loaded.

  <leader>io / <leader>iq   Review on / off
  <leader>is               Structural review
  <leader>ib / <leader>ih   Choose base / head
  <leader>if / <leader>ic   Changed files / commits
  <leader>ir               Clean range diff
  <leader>in / <leader>ip   Next / previous commit
  <leader>it               Switch between Review and Source
  <leader>iv / <leader>iV   Toggle reviewed / changes since review
  <leader>id / <leader>iw   Deleted lines / diff window (structural mode)

Existing mappings on these keys are preserved. Change the prefix with
`keymaps = { prefix = "<leader>m" }`, or disable all defaults with `keymaps = false`.
Repeated setup() removes only mappings still owned by Incognito, keeping user
replacements. Commands and Lua functions remain available for custom mappings.

`commit_mode.link` names ignored directories of your checkout, at any
depth, that are symlinked into the commit mode worktree. When a commit's
`commit_mode.lockfiles` differ from your checkout, a warning says that the
linked dependencies may not fit it. Default link={} avoids shared dependency
writes. Opt-in links are NOT isolated: an external write can change Source.
The plugin refuses opening/writing through Review links. The worktree_dir
parent defaults to a sibling <canonical-Source>.incognito; changing it does
not move existing experiments.

4. HIGHLIGHTS                                                *incognito-highlights*

  StructDiffFormat        Lines changed only in formatting (NonText)
  StructDiffAddInline     Added tokens (DiffAdd)
  StructDiffChangeInline  Changed tokens (DiffAdd)
  StructDiffDeleteInline  Deleted tokens (DiffDelete)

Line signs reuse GitSignsAdd, GitSignsChange and GitSignsDelete.

==============================================================================
5. LIMITATIONS                                               *incognito-limitations*

- difftastic JSON output is unstable and needs `DFT_UNSTABLE=yes`.
- Review is persistent, not scratch. Off/exit never remove/reset its disk.
  There is no autosave. :wqa writes; :qa protects modified buffers; :qa! and
  crash can lose unsaved memory. Off leaves modified Review buffers accessible.
- A real N transition/new R for the same owner discards staged, unstaged,
  non-ignored untracked files and unsaved Review buffers/undo without a dialog.
  Ignored artifacts survive, so the environment is not reproducibly clean.
  Review buffers disable persistent undo; old N history cannot reload later.
  Same N/R, cancelled pickers and list boundaries do not discard anything.
- One Review per repository+owner branch. Branch head selections own Review;
  revision/SHA selections use the Source branch. Detached Source requires an
  explicit owner (picker or Lua change_head(rev, owner)). Another owner keeps
  its previous disk. Source HEAD/index/cwd are not switched.
- One editor owns Review until exit (also after off while writable buffers
  remain). Dead locks can be reclaimed without deleting data; inaccessible
  processes stay locked. Linux verifies boot/start identity as well as PID.
  A stale .lock.gate needs manual inspection when all owners are stopped.
- Ownership, canonical paths and Review's own administrative Git directory are
  checked before reset. Unknown paths/old scratch worktrees are never deleted.
  External HEAD movement, unmerged index, external Git operations, nested Git,
  submodules/mounts, sparse/skip-worktree/assume-unchanged state or ignored-target
  collisions require manual handling. Plugin workspace Git hooks are disabled.
  Partial Git/FS failures have no rollback guarantee: inspect the manifest and
  files manually; the next entry will not reset an interrupted transition.
- No shell sandbox: manual Source opens, hardlinks, external writers and user
  autocmds are outside these guards. Stop agents before changing N. There is
  no automatic merge of agent/editor changes or force-reload of modified text.
- No Codex context, agent launcher, build runner, amend/rebase/apply. Run those
  tools manually in Review; commands in Source are not silently redirected.
- No forge integration.
